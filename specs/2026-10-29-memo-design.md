# Flow 메모 설계

2026-10-29 · 상태: 검토 대기

## 왜

지금 Flow 는 한 줄짜리 할 일만 적을 수 있다. 쓰는 사람은 **업무 절차를 길게 정리**하는 편이라,
Simplenote 같은 메모를 Flow 안에서 쓰고, 그 절차를 매일 하는 루틴·할 일에 붙여 두고 싶다.

**성공의 기준:** 긴 업무 절차를 Flow 안에서 불편 없이 쓰고, 다시 찾고, 매일 따라 할 수 있다.
PC 위젯의 가벼움과 '하루가 지나면 저절로 풀림'은 그대로다.

### 정한 것 (대화에서 고른 답)

| 질문 | 답 |
|---|---|
| 긴 글은 어디에 | 할 일 메모 + 따로 쓰는 메모, 둘 다 |
| 휴대폰에서는 | 보기 · 쓰기 · 고치기 전부 (겹치면 충돌 사본) |
| 글 모양 | 글로 적고, 읽을 때만 가벼운 서식으로 보임 |
| 메모 안 체크 칸 | 메모마다 '매일 초기화' 켤 수 있음 + '체크 모두 풀기' 버튼 |
| PC 에서 쓰는 곳 | 위젯과 따로 뜨는 메모 창 (왼쪽 목록 · 오른쪽 본문) |
| 할 일 메모와 메모의 관계 | 메모는 한 종류. 할 일·루틴은 메모를 **연결**한다 |
| 정리 | 검색 + 📌 고정 + `#태그` |
| 저장 | 메모 하나 = 파일 하나 |

### 하지 않는 것

굵게·색깔·표 같은 서식, 그림·첨부, 메모 변경 이력, 남과 공유, 태그 이름 일괄 바꾸기.
필요해지면 그때 따로 정한다.

## 1. 화면

### PC 위젯

- 탭: `오늘 · 루틴 · 예정 · 메모`
- **메모 탭**
  - 위: 검색칸. 제목과 본문에서 찾는다(대소문자 무시). `#태그` 를 치면 그 태그로 거른다.
  - 그 아래: 태그 줄. 누르면 그 태그 메모만, 다시 누르면 해제.
  - 목록: 📌 고정 먼저, 그다음 최근에 고친 순. 한 줄에 제목 + 본문 첫머리(흐리게), 매일 초기화 메모는 ↻.
  - 아래 입력칸에 적고 Enter → 그 글을 제목으로 새 메모를 만들고 메모 창으로 연다.
- **할 일·루틴 줄**
  - 메모가 연결돼 있으면 오른쪽에 📝. 누르면 메모 창이 그 메모로 열린다(체크되지 않는다).
  - 우클릭 메뉴: `메모 연결 ▸ 새로 만들기 / 있는 메모 고르기 / 연결 끊기`
  - 줄을 누르면 체크 — 지금과 같다.

### PC 메모 창 (새 창)

- 왼쪽: 메모 목록(위젯 메모 탭과 같은 목록·검색·태그). 맨 아래 `휴지통`.
- 오른쪽: 본문.
  - **읽기 모드(기본):** 서식이 정리돼 보이고 체크 칸을 바로 누를 수 있다.
  - **쓰기 모드:** 본문을 누르거나 Ctrl+E. 적은 글 그대로 보인다. Esc 또는 Ctrl+E 로 읽기 모드.
  - 첫 줄이 제목.
- 본문 위 도구 줄: 📌 고정 · ↻ 매일 초기화 · 체크 모두 풀기 · 연결된 할 일(누르면 목록) · 삭제
- 창 크기·위치는 이 PC 에만 기억한다(`DeviceState`, 위젯 위치와 같은 곳). 위젯을 끄면 같이 닫힌다.
- 열 때 만들고 닫으면 완전히 없앤다.

### 가벼운 서식 (읽기 모드)

줄 단위로만 본다. 줄 안의 꾸밈(굵게 등)은 없다.

| 적은 것 | 보이는 것 |
|---|---|
| `# 글` · `## 글` | 소제목(큰 · 조금 큰) |
| `1. 글` (숫자 + 점 + 띄어쓰기) | 번호 단계 |
| `- 글` · `* 글` | 점 목록 |
| `[ ] 글` · `- [ ] 글` | 빈 체크 칸 |
| `[x] 글` · `- [x] 글` (`X` 도) | 체크된 칸 (글은 흐리게) |
| 빈 줄 | 문단 사이 |
| 그 밖 | 보통 글 |

- **태그:** 줄 어디서든 `#` 바로 뒤에 공백 아닌 글자가 붙은 낱말(`#AK넷`, `#정산`). `# 준비` 처럼 띄우면 소제목이지 태그가 아니다.
  태그는 글에 그대로 남고, 읽기 모드에서는 작은 칩으로 보인다.
- 체크 칸을 누르면 그 줄의 `[ ]` ↔ `[x]` 만 바꿔 저장한다.

### 휴대폰

- 위에 `오늘 | 메모` 두 탭.
- 메모 탭: 검색 · 태그 · 목록은 PC 와 같다. 누르면 전체 화면으로 열린다(읽기 모드, 체크 칸 누르기 가능).
  오른쪽 위 `고치기` → 글로 고친다. 고정 · 매일 초기화 · 체크 모두 풀기 · 삭제도 여기서.
- 오늘 화면의 할 일·루틴에 📝 → 누르면 그 메모.
- 길게 눌러 여는 고치기 창에 `메모 연결` 추가(새로 만들기 / 고르기 / 끊기).

## 2. 저장

### 위치

데이터 폴더(`data.json` 이 있는 곳) 안 `memos\`. 메모 하나 = `.md` 파일 하나.
데이터 폴더가 구글 드라이브면 메모도 그대로 따라간다.

```
data\
  data.json
  memos\
    AK넷 일별 정책서 배포.md
    정산 절차.md
    휴지통\
      옛 메모.md
```

### 파일 모양

```
---
id: 3f2a9c1e-…
pinned: true
daily: true
reset: 2026-10-29
---
AK넷 일별 정책서 배포 #AK넷

# 준비
1. 정책서 엑셀 받기
[x] 단가표 확인
[ ] 오전 11~12시 사이 배포
```

- 머리말(`---` 사이): Flow 가 쓰는 표시. 메모 창에는 보이지 않는다.
  - `id` 메모 번호(Guid). 메모를 알아보는 유일한 기준. 파일 이름이 아니다.
  - `pinned` 고정. 없으면 false.
  - `daily` 매일 초기화. 없으면 false.
  - `reset` 매일 초기화로 마지막으로 체크를 푼 논리적 날짜.
  - `deleted` 휴지통에 들어간 날(휴지통 안에서만).
  - 모르는 키는 그대로 보존한다(새 버전이 더한 키를 옛 버전이 지우지 않게).
- 본문: 머리말 다음 전부. 첫 줄(앞뒤 공백 제외, 태그 포함 그대로)이 제목. 제목이 비면 `제목 없음`.
- 인코딩 UTF-8(BOM 없음), 줄바꿈은 읽을 때 무엇이든 받고 쓸 때 `\r\n`.
- **머리말이 없거나 깨진 파일**(직접 넣은 `.md`·`.txt`): 전체를 본문으로 읽고, 임시 id 는 파일 경로에서 만든다.
  처음 고치거나 연결할 때 머리말을 붙이고 진짜 id 를 준다.

### 파일 이름

- 제목에서 만든다: Windows 에서 못 쓰는 글자(`\ / : * ? " < > |`, 제어 문자)는 지우고, 앞뒤 공백·점을 떼고, 60자에서 자른다.
  예약된 이름(`CON`, `NUL` …)이나 빈 이름이면 `메모`.
- 같은 이름이 있으면 `이름 (2).md`, `(3)` …
- 제목이 바뀌면 저장할 때 파일 이름도 바꾼다.

### 저장 시점

- 쓰는 동안 입력이 1초 멈추면, 그리고 메모를 바꾸거나 창을 닫을 때.
- 임시 파일(`이름.md.tmp`)에 다 쓴 뒤 바꿔치기(`File.Replace` / `File.Move`). `data.json` 과 같은 방식.
- 데이터 폴더를 기다리는 중(드라이브 꺼짐)이면 쓰지 않는다 — 지금의 노란 띠 규칙과 같다.

### 할 일·루틴 연결

- `Routine.MemoId`, `TaskItem.MemoId` (Guid?, `data.json`). 없는 옛 파일은 null 로 읽힌다.
- 연결된 메모가 없으면(지워짐·휴지통) 📝 를 그리지 않는다. 메모를 되살리면 다시 보인다 — 연결 값은 지우지 않는다.
- 여러 할 일·루틴이 같은 메모를 가리킬 수 있다.

### 매일 초기화

- PC 가 롤오버(`DayEngine.Rollover`)를 돌 때, 같은 자리에서 `daily: true` 이고 `reset < 오늘` 인 메모의
  `[x]`/`[X]` 를 `[ ]` 로 바꾸고 `reset: 오늘` 을 적는다.
- PC 가 둘이어도 `reset` 을 보고 하루 한 번만 푼다. 이미 오늘 푼 파일은 건드리지 않는다.
- '체크 모두 풀기' 버튼은 날짜와 상관없이 지금 푼다(`reset` 은 바꾸지 않는다).

### 삭제와 휴지통

- 삭제 = `memos\휴지통\` 으로 옮기고 `deleted: 오늘` 을 적는다.
- 휴지통에서 되살리기 = 다시 `memos\` 로(이름이 겹치면 `(2)`).
- PC 가 켜질 때 `deleted` 가 30일 지난 것을 지운다.

### 백업

- 백업 파일을 `.json` 하나에서 **`.zip`** 하나로 바꾼다: `data.json` + `memos\`(휴지통 제외).
- 되돌리기: zip 이면 둘 다 되돌린다. 메모는 '백업에 있는 메모로 맞추고, 백업에 없는 지금 메모는 휴지통으로' 옮긴다(바로 지우지 않는다).
- 예전 `.json` 백업으로 되돌리면 `data.json` 만 되돌리고 메모는 건드리지 않는다.
- 되돌리기 직전 자동 백업도 zip 으로.

## 3. 여러 곳에서 같이 고칠 때

원칙: **남이 쓴 글을 말없이 덮어쓰지 않는다.** 겹치면 둘 다 남기고 알린다.

### 판(版)

메모의 판 = 머리말을 뺀 본문의 해시(SHA-256 앞 16자). 머리말만 바뀐 것(고정 등)은 판이 그대로다.

### PC 여러 대

- `memos\` 를 10초마다 훑는다. 파일마다 (크기, 고친 시각)을 기억해 두고 바뀐 것만 읽는다.
- 바뀐 메모가 메모 창에 열려 있으면:
  - 쓰기 중이 아님(저장 안 한 글 없음) → 새 내용으로 바꿔 보여 준다.
  - 저장 안 한 글이 있음 → 아래 '저장할 때 검사'로 간다.
- **저장할 때 검사:** 이 창이 그 메모를 연(또는 마지막으로 저장한) 판과 지금 파일의 판을 비교한다.
  다르면 파일은 그대로 두고, 내 글을 **새 메모 `제목 (충돌 사본 MM-dd HH:mm)`** 으로 저장한다(새 id, 연결 없음).
  메모 창 위에 노란 띠: "다른 곳에서 먼저 고쳐서, 내 글은 충돌 사본으로 따로 남겼습니다". 창은 원래 메모의 새 내용을 보여 준다.
- **같은 id 가 둘**(드라이브가 만든 `이름 (1).md` 등): 고친 시각이 늦은 쪽이 원래 메모. 다른 쪽은 새 id 를 받고 제목 첫 줄 끝에 ` (충돌 사본)` 을 붙여 저장한다.

### 휴대폰이 받는 것

- `phone-view.json` 에 `Memos` 를 더한다. 옛 휴대폰은 모르는 필드라 건너뛴다.
- **중계 스크립트(relay.gs)는 바꾸지 않는다** — 이미 `phone-view.json` 을 그대로 넘긴다.
- 메모 항목: `Id, Title, Text(본문 전체), Pinned, Daily, Rev(판), Updated(고친 시각)`. 휴지통 것은 넣지 않는다.
- 오늘 화면의 `Routines`·`Tasks`·`Upcoming` 항목에 `MemoId` 를 더한다.
- 휴대폰은 30초마다 새로고침할 때 메모 본문까지 받는다. 화면을 열어 둔 동안만.

### 휴대폰이 보내는 일 (phone-inbox.json)

지금처럼 '이렇게 맞추기' 꼴이라 두 번 와도 결과가 같다. 모르는 갈래는 옛 PC 가 건드리지도 적지도 않는다.

| Kind | Target | Text | 그 밖 | PC 가 하는 일 |
|---|---|---|---|---|
| `memo-save` | 메모 id | 본문 전체 | `Base`: 보고 고친 판(새 메모면 없음) | 메모가 없으면 그 id 로 새로 만든다. 있고 지금 판 == `Base` 면 덮어쓴다. 다르면 **`제목 (휴대폰 충돌 사본)`** 새 메모로 저장. 같은 글이면 건너뜀 |
| `memo-check` | 메모 id | 그 줄의 글(체크 표시 뺀 것) | `Line`: 몇째 줄, `Checked` | `Line` 줄이 그 글이면 그 줄을, 아니면 같은 글의 체크 줄 중 첫째를 `Checked` 로 맞춘다. 없으면 건너뜀 |
| `memo-pin` | 메모 id | `true`/`false` | | 고정 맞추기 |
| `memo-daily` | 메모 id | `true`/`false` | | 매일 초기화 맞추기 |
| `memo-uncheck-all` | 메모 id | | | 체크 모두 풀기 |
| `memo-delete` | 메모 id | | | 휴지통으로. 이미 없으면 건너뜀 |
| `memo-link` | 할 일·루틴 id | 메모 id 또는 빈 글 | | `MemoId` 맞추기(빈 글이면 끊기) |

`PhoneOp` 에 `Line`(int?)·`Checked`(bool?)·`Base`(string?) 를 더한다. 없는 옛 파일은 null.
`PhoneApplyResult` 에 메모 몫(`MemoChanged`, `MemoConflicts`)을 더하고, PC 알림에 "메모 고침 n · 충돌 사본 n" 을 붙인다.

- 휴대폰은 PC 가 아직 받지 않은 메모 일을 화면에 얹어 보여 준다(지금 할 일과 같은 방식, 'PC 반영 대기').
- 휴대폰에서 고치는 동안 30초 새로고침이 와도 고치던 글은 그대로 둔다.

### 업데이트 순서

PC 를 먼저, 휴대폰 화면은 그다음. 순서가 바뀌어도 옛 PC 는 모르는 메모 일을 inbox 에 남겨 두므로 PC 가 올라가면 반영된다.

## 4. 구성

| 새 / 바뀜 | 이름 | 하는 일 |
|---|---|---|
| 새 | `Models/Memo.cs` | 메모 한 개(Id, 본문, Pinned, Daily, Reset, Deleted, 모르는 머리말 키, 파일 경로, 판) |
| 새 | `Services/MemoFormat.cs` | 순수 함수: 파일 글 ↔ Memo(머리말), 제목, 태그, 판, 줄 분류(소제목·번호·점·체크·글), 체크 바꾸기, 모두 풀기, 파일 이름 만들기 |
| 새 | `Services/MemoStore.cs` | 폴더 읽기·훑기(바뀐 것만), 저장(임시 파일 → 바꿔치기, 이름 바꾸기, 같은 이름), 판 검사·충돌 사본, 휴지통·되살리기·30일 정리, 같은 id 정리, 매일 초기화 |
| 새 | `ViewModels/MemoListViewModel.cs` | 목록·검색·태그 거르기(위젯 탭과 메모 창이 같이 쓴다) |
| 새 | `ViewModels/MemoEditorViewModel.cs` | 열린 메모, 읽기/쓰기 모드, 1초 자동 저장, 충돌 띠 |
| 새 | `Views/MemoWindow.axaml(.cs)` | 메모 창 |
| 바뀜 | `Models/AppData.cs` | `Routine.MemoId`, `TaskItem.MemoId` |
| 바뀜 | `Models/DeviceState.cs` | 메모 창 위치·크기 |

## 5. 오류와 안전

- 파일 쓰기는 늘 임시 파일 → 바꿔치기. 실패하면 화면의 글은 그대로 두고 메모 창에 "저장하지 못했습니다 · 다시 시도 중" 띠, 5초마다 다시.
- 못 읽는 파일(잠김·깨진 인코딩)은 목록에 흐리게 "읽지 못함"으로 두고 건너뛴다. 지우지 않는다.
- `memos\` 가 없으면 처음 메모를 만들 때 만든다. 메모를 안 쓰는 사람에게는 폴더도 생기지 않는다.
- 메모가 아주 많아도 위젯은 제목·첫머리·판만 들고 있는다(본문은 열 때 읽음). 첫머리는 앞 80자.

## 6. 시험

자동(`Tests/Flow.Tests`, 릴리스 때 GitHub 에서 다 통과해야 나감):

- 머리말 읽기·쓰기 왕복, 모르는 키 보존, 머리말 없는/깨진 파일
- 제목·태그(`#태그` vs `# 소제목`)·줄 분류·판(머리말만 바뀌면 그대로)
- 파일 이름: 못 쓰는 글자, 예약 이름, 60자, 같은 이름 `(2)`, 제목 바뀌면 이름 바뀜
- 저장: 판이 같으면 덮어씀, 다르면 충돌 사본(새 id, 원본 그대로)
- 같은 id 둘 → 늦은 쪽 원본, 다른 쪽 충돌 사본
- 매일 초기화: 하루 한 번만, `daily: false` 는 그대로, 체크 모두 풀기
- 휴지통: 넣기·되살리기(이름 겹침)·30일 정리
- 백업 zip: 메모 포함, 되돌리면 백업에 없는 메모는 휴지통, 옛 `.json` 백업은 메모 그대로
- 휴대폰 메모 일: 새 메모, 판 같음/다름(충돌 사본), 체크(줄 번호 맞음/밀림/없음), 고정·매일·모두 풀기·삭제·연결, 두 번 와도 같음, 모르는 갈래
- `phone-view.json` 에 `Memos`·`MemoId` 가 들어가고 휴지통 것은 빠짐

휴대폰: 보기용(`?demo`) 데이터와 가짜 중계(실제 relay.gs 실행)로 눌러 보며 확인.

## 7. 만드는 순서

단계마다 버전을 하나씩 낸다.

| 단계 | 내용 | 끝나면 |
|---|---|---|
| 1 | `MemoFormat`·`MemoStore`, 메모 창, 메모 탭, 가벼운 서식, 검색·고정·태그, 휴지통, zip 백업, PC 끼리 판 검사·충돌 사본 | PC 에서 절차서를 쓰고 찾는다 |
| 2 | 할 일·루틴 ↔ 메모 연결(📝, 우클릭), 매일 초기화, 체크 모두 풀기 | 루틴에 절차를 붙여 매일 따라 한다 |
| 3 | 휴대폰: `Memos` 받기, 메모 탭 보기, 체크 칸(`memo-check`), 📝 | 밖에서 절차를 확인한다 |
| 4 | 휴대폰: 쓰기·고치기·고정·매일·모두 풀기·삭제·연결, 충돌 사본 | 휴대폰에서도 전부 |
