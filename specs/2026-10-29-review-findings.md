### 지금 흐름

- PC 는 중계에 직접 닿지 않는다. `Flow 폰` 폴더(데이터 폴더에서 위로 3단계 안, `PhoneLinkStore.cs:60-77`)의 두 파일만 읽고 쓰고, 드라이브 데스크톱 앱이 드라이브와 맞춘다. 중계(relay.gs)는 휴대폰이 같은 드라이브 파일에 닿는 길. → OneDrive 데이터 폴더면 휴대폰 연동이 안 됨(README 에 없음).
- PC: 10초마다 inbox 시각·크기만 봄(`MainViewModel.cs:235-237, 1435-1442`), 1분마다 다시 넣고 화면 파일 씀(`:282-289, 1418-1426`). 할 일 · 루틴 바꾸면 2초 뒤 씀(`:228-233`). 내용이 같으면 안 씀.
- **PC 메모 변경(읽기 모드 체크, 고정, 삭제 · 되살리기, 빠른 메모, 다른 곳에서 고친 것)은 2초 타이머를 안 걸어 최대 1분 기다린다**(`RefreshMemoList`, `MainViewModel.cs:1773`).
- 휴대폰: 보일 때만 30초마다, 다시 보이면 바로 새로고침(`app.js:30, 2025-2031`). 일은 localStorage 에 먼저 넣고 0.7초 뒤 보냄. 보낸 뒤 바로 다시 받지는 않음.
- 숨겨지면 아무것도 안 보냄. `online` 이벤트 없음, 요청 시간 제한 없음 — 멈춘 요청이 `refreshing` 을 잡고 있으면 뒤 새로고침이 다 같은 요청을 기다림(`app.js:466-470`).
- 한 바퀴(휴대폰 체크 → PC → 휴대폰): 보통 15–60초 'PC 반영 대기'.
- AppliedOps 는 45일 치를 매번 화면 파일에 다 넣음(`PhoneLinkEngine.cs:254, 603`) — 하루 50개면 약 86KB, 무작위 id 라 압축도 잘 안 됨. 메모 150개(1.5KB) + 이것 ≈ 290KB 를 30초마다 받고 · 저장하고 · 두 번 그림.
- 오류 문구: 그냥 오프라인이어도 "액세스 권한이 '모든 사용자'인지 확인하세요"(`app.js:358-364`). JSON 이 아닌 답(잠금 시간 초과 · 드라이브 오류)도 모두 권한 문제로 봄.
- 휴대폰은 PC 가 켜졌는지 모름: "PC n분 전 기준"은 내용이 바뀔 때만 바뀌는 `GeneratedAt` 이라, 켜져 있지만 조용한 PC 와 꺼진 PC 가 같아 보임. PC 에는 휴대폰 연동 상태 표시가 아예 없음.

잘 된 것: 파일마다 쓰는 쪽이 하나, 일은 상태를 정하고(뒤집지 않음) Id 가 있어 두 번 와도 무해, 중계가 잠금 걸고 Id 로 합침, 보내기 전 휴대폰에 저장, 못 넣는 일은 inbox 에 남김, 같은 내용이면 안 씀.
