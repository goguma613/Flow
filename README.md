# Flow

항상 화면에 띄워두는 할 일 위젯. **하루가 지나면 반복 루틴 체크가 자동으로 풀리고 날짜가 바뀝니다.**

Todoist의 입력 속도, TickTick의 습관 트래커, Things 3의 여백 중심 디자인을 한 패널에 압축했습니다.
협업·클라우드·캘린더는 넣지 않았습니다 — 그게 가벼움의 핵심입니다.

---

## 실행

```
dist\Flow.exe
```

설치가 필요 없는 단일 실행 파일입니다(.NET 런타임 포함, 50MB).
바탕화면이나 시작 메뉴에 바로가기를 만들어 두고, 설정에서 **부팅 시 자동 시작**을 켜면 됩니다.

- 창을 닫는 X 버튼은 **완전 종료**입니다.
- 옆의 `—` 버튼은 **트레이로 숨기기**입니다. 트레이 아이콘을 클릭하거나 **Ctrl + Alt + Space**로 다시 불러옵니다. 이 조합은 설정 · 앱에서 바꾸거나 끌 수 있습니다.
- 헤더의 날짜 부분을 잡고 끌면 창이 이동합니다. 위치는 옮긴 즉시 저장되며, 보조 모니터에 둬도 그대로 유지됩니다.
- 오른쪽 아래 모서리(또는 오른쪽·아래 가장자리)를 끌면 크기가 조절됩니다. 모서리를 두 번 클릭하면 내용에 맞는 높이로 돌아갑니다.
- 창을 400px보다 낮게 줄이면 머리말이 접힙니다. 요일과 진행률 막대를 감추고 목록에 자리를 내줍니다(진행 상황은 날짜 옆에 숫자로 남습니다).
- 오른쪽 위 `?` 버튼에 앱 안 사용법이 있습니다. 첫 실행에는 자동으로 뜹니다.
- 새 버전은 **스스로 받아옵니다.** 자세한 건 아래 [자동 업데이트](#자동-업데이트)를 보세요.

## 화면

| 탭 | 내용 |
|---|---|
| **오늘** | 오늘 예정된 반복 루틴 + 오늘 마감인 할 일. 완료 항목은 접혀 있습니다. |
| **루틴** | 최근 4주 달성률 히트맵, 전체 루틴 목록(요일·연속 기록) |
| **예정** | 내일 이후 마감인 할 일 |

**행 아무 곳이나 클릭하면 완료 처리**됩니다. 작은 동그라미를 정확히 노릴 필요가 없습니다.
마우스를 올리면 오른쪽에 삭제 버튼이 나타나고, **우클릭하면 이름 바꾸기·우선순위 변경·삭제**를 할 수 있습니다.

`루틴` 탭에서 오늘 예정이 아닌 요일의 루틴은 동그라미 대신 점으로 표시되고 체크할 수 없습니다 — 화·목 루틴을 월요일에 체크하면 연속 기록이 어긋나기 때문입니다.

## 빠른 추가 문법

맨 아래 입력창에 한 줄로 적고 Enter. 입력하는 동안 해석 결과가 초록색으로 미리 표시됩니다.

### 반복 루틴 (하루가 지나면 자동으로 체크 해제)

| 입력 | 결과 |
|---|---|
| `매일 물 2L 마시기` | 매일 반복 |
| `평일 스탠드업` | 월~금 반복 |
| `주말 대청소` | 토·일 반복 |
| `매주 월수금 운동 30분` | 월·수·금 반복 |
| `매주 월요일 주간보고` | 매주 월요일 |
| `월수금 저녁 운동` | 월·수·금 반복 |
| `화목 재고 점검` | 화·목 반복 |

요일 글자가 두 개 이상 붙어 하나의 낱말을 이루면(`월수금`, `화목`) 어느 탭에서든 반복 루틴이 됩니다.
`수목원 가기`처럼 낱말 속에 우연히 들어간 경우는 걸러집니다. `루틴` 탭에서는 `매일` 같은 말 없이 적어도 전부 루틴이 됩니다.

### 할 일

| 입력 | 결과 |
|---|---|
| `장부 정리` | 오늘 마감 |
| `내일 오후 3시 정책 회의` | 내일 15:00 |
| `모레 세금 신고` | 모레 |
| `수요일 팀 회의` | 다음 수요일 |
| `9/15 사은품 정산` | 9월 15일 |
| `9월 20일 마감` | 9월 20일 |
| `25일 결산` | 이번 달 25일 (지났으면 다음 달) |
| `14:30 고객 통화` | 오늘 14:30 |
| `3시 반 미팅` | 오늘 03:30 |

### 우선순위

문장 끝에 붙입니다. 체크 동그라미 테두리 색으로 표시됩니다.

| 표기 | 의미 | 색 |
|---|---|---|
| `!1` 또는 `p1` | 최우선 | 빨강 |
| `!2` `p2` | 보통 | 주황 |
| `!3` `p3` | 낮음 | 파랑 |
| `!4` `p4` | 없음 | 회색 |

**조합 예시:** `내일 오후 3시 보고서 제출 !1` → 내일 15:00 마감, 최우선, 제목은 "보고서 제출"

## 자동 초기화가 동작하는 방식

이 앱의 핵심입니다.

### 논리적 날짜

실제 자정이 아니라 **하루 시작 시각**(기본 04:00)을 기준으로 날짜를 셉니다.
새벽 2시에 루틴을 체크해도 전날 것으로 집계되므로, 늦게까지 일하는 날에 기록이 억울하게 끊기지 않습니다.
설정에서 00시~23시 사이로 바꿀 수 있습니다.

### 날짜가 넘어갈 때 일어나는 일

1. 지나간 하루를 결산해 기록에 남깁니다 (히트맵·연속 기록의 원본)
2. 모든 루틴 체크를 해제합니다
3. 헤더 날짜를 갱신하고 `새 하루 시작 · 루틴을 초기화했습니다`를 잠깐 표시합니다
4. 끝내지 못한 할 일을 오늘로 이월하고 `밀림 N일`을 붙입니다 (설정에서 끌 수 있음)
5. 요일 지정 루틴은 해당 요일이 아니면 목록에서 숨깁니다

### PC를 며칠 꺼놨다면

켜는 즉시 그 기간 전체를 한 번에 정산합니다. 3일을 쉬었으면 3일치가 기록되고, 빠진 날이 있으면 연속 기록이 끊깁니다.
확인 주기는 30초이며, 절전에서 깨어나거나 창을 클릭할 때도 즉시 확인합니다.

### 연속 기록 (스트릭)

예정된 날에 완료할 때마다 1씩 올라가고, 예정된 날을 건너뛰면 0으로 돌아갑니다.
요일 루틴은 **예정된 날끼리** 이어집니다 — 월·수·금 루틴이라면 금요일 다음은 월요일이므로, 주말은 연속에 영향을 주지 않습니다.
체크를 실수로 눌렀다가 해제하면 이전 값이 정확히 복원됩니다.

## 성능 (이 PC에서 실측)

| 항목 | 실측값 |
|---|---|
| 유휴 CPU | **0%** (60초 동안 누적 0ms) |
| 메모리 (실사용) | **52MB** — 작업 관리자의 "메모리" 열은 131MB로 보입니다\* |
| 트레이로 숨겼을 때 | **32MB** (사용하지 않는 페이지를 OS에 반납) |
| 시작 시간 | **224ms** |
| 스레드 | 8개 |
| 실행 파일 | 50MB (.NET 런타임 포함, 설치 불필요) |

\* 작업 관리자가 보여주는 값(Working Set)에는 메모리에 매핑된 실행 파일과 다른 앱과 공유하는 런타임 페이지가 포함됩니다. 실제로 이 앱만 차지하는 양(Private bytes)은 52MB입니다.

**참고 — 같은 PC의 다른 앱:** Chrome 2,076MB · Excel 219MB · 카카오톡 458MB.
Todoist 데스크톱 앱은 Electron 기반이라 보통 300MB 이상 씁니다.

가볍게 만든 방법:
- GPU 컨텍스트(ANGLE) 대신 소프트웨어 렌더링 — 340px 정적 패널에는 GPU가 과합니다 (스레드 43→17, 메모리 171→135MB)
- 아크릴 블러 제거 — 매 프레임 배경을 다시 샘플링합니다
- 유휴 시 타이머는 30초에 한 번 날짜 비교 하나뿐. 애니메이션은 마우스를 올렸을 때만 돕니다
- DB 엔진도, 백그라운드 프로세스도, 네트워크 연결도 없습니다

## 자동 업데이트

**앱을 켤 때마다** 한 번, 시작 20초 뒤에 [GitHub Releases](https://github.com/goguma613/Flow/releases)를 확인합니다.
껐다 켜지 않고 며칠씩 두는 경우를 위해 20시간마다 한 번 더 봅니다.
요청 한 건에 수 KB라 평소 동작에는 영향이 없고, 인터넷이 없거나 GitHub이 응답하지 않아도 조용히 넘어갑니다.

새 버전이 있으면 백그라운드로 받아둔 뒤 입력칸 위에 `새 버전 1.0.1 준비됨 · 지금 재시작 →` 막대를 띄웁니다.
누르면 교체하고 다시 시작합니다.

실행 중인 exe는 덮어쓸 수 없지만 **이름은 바꿀 수 있습니다.** 그 성질을 이용해 헬퍼 스크립트 없이 자기 자신을 교체합니다.

1. 실행 중인 `Flow.exe` → `Flow.exe.old` 로 이름 변경
2. 받아둔 파일을 `Flow.exe` 자리에 복사
3. 새 exe 실행 후 현재 프로세스 종료
4. 다음 시작 때 `.old` 정리

복사에 실패하면 원래 파일을 되돌려 놓습니다. 앱이 사라지는 일은 없습니다.

**설정에서 끄면 인터넷을 전혀 쓰지 않습니다.**

### 새 버전 내기

```powershell
.\release.ps1 1.0.1 -Notes "최소화 버튼이 안 보이던 문제를 고쳤습니다"
```

버전 올리기 → 빌드 → 커밋·태그·푸시 → 릴리스 업로드까지 한 번에 합니다.
처음 한 번은 `gh auth login` 이 필요합니다.

릴리스 자산의 이름은 **반드시 `Flow.exe`** 여야 합니다. 앱이 그 이름으로 찾습니다.

## 데이터

```
<Flow.exe 가 있는 폴더>\data\data.json
```

**실행 파일 옆에 저장합니다.** 앱을 여러 벌 두면(실제 사용본 · 시험본) 각자 자기 데이터를 쓰므로 서로 건드리지 않습니다.
폴더째 옮기면 적어둔 내용도 따라갑니다.

폴더에 쓸 수 없는 위치(예: Program Files)라면 `%APPDATA%\Flow` 로 물러납니다.
`FLOW_DATA_DIR` 환경 변수를 주면 그 경로를 씁니다 — 개발 중 실제 데이터를 건드리지 않으려고 둔 장치입니다.

예전 버전이 쓰던 `%APPDATA%\Flow\data.json` 이 있으면 처음 한 번 **복사해** 옵니다. 원본은 지우지 않습니다.

지금 쓰는 경로는 설정 맨 아래에 표시됩니다.

JSON 파일 하나입니다. 열어서 직접 고쳐도 되고, 복사해 두면 그게 백업입니다.
저장은 임시 파일에 쓴 뒤 교체하는 방식이라 쓰는 도중에 전원이 꺼져도 원본이 깨지지 않습니다 (`data.json.bak`이 직전 버전).

저장에 실패하면 같은 폴더의 `error.log`에 남습니다. 평소에는 이 파일이 생기지 않습니다.

기록은 1년치, 완료한 할 일은 7일치 보관 후 자동 정리됩니다.

## 백업

`data.json` 을 실행 파일 옆 `dataackup\` 으로 복사해 둡니다.

- **하루에 한 번** — 그날 처음 켤 때
- **업데이트를 적용하기 직전**
- 설정에서 **직접** 만들 수도 있습니다

최근 20개를 보관하고 오래된 것부터 지웁니다. 파일 하나가 몇 KB라 자리를 거의 차지하지 않습니다.

### 되돌리기

설정 → 백업 → `백업에서 되돌리기` 에서 시점을 골라 되돌립니다. 각 항목에 그 시점의 루틴·할 일 개수가 표시되므로 무엇을 고르는지 알 수 있습니다.

**되돌리기 직전 상태도 자동으로 백업**되므로, 잘못 골라도 다시 돌아올 수 있습니다.

되돌린 뒤에는 앱을 다시 켜지 않아도 그 자리에서 새 내용을 읽어들입니다.

> 백업 파일 이름에는 밀리초까지 넣습니다. 초 단위만 쓰면 같은 초에 두 번 백업할 때 이름이 겹쳐 앞의 것이 사라지는데, 하필 그 앞의 것이 "되돌리기 직전" 안전망이라 실제로 위험합니다.

## 개발

```bash
# 빌드
dotnet build Flow/Flow.csproj

# 자체 검증 (롤오버 엔진 · 파서 · 직렬화 · 백업, 137개)
dotnet run --project Tests/Flow.Tests

# 배포용 단일 exe
dotnet publish Flow/Flow.csproj -c Release -o dist
```

빌드 후 `dist` 폴더의 `libHarfBuzzSharp.pdb`, `libSkiaSharp.pdb`는 실행에 필요 없으니 지워도 됩니다.

### 구조

```
Flow/
  Models/AppData.cs          데이터 모델 전체
  Services/
    DayEngine.cs             날짜 롤오버 엔진 (순수 함수 — 시간을 주입해 테스트)
    QuickAddParser.cs        한국어 자연어 파서
    DataStore.cs             JSON 원자적 저장
    GlobalHotKey.cs          전역 단축키 (조합은 설정에서 바꿀 수 있다)
    HotKeyCombo.cs           그 조합을 읽고 쓰는 순수 코드
    StartupService.cs        부팅 시 자동 시작 등록
    UpdateService.cs         GitHub Releases 기반 자동 업데이트
    BackupService.cs         백업 만들기 · 목록 · 되돌리기
  ViewModels/                MainViewModel + 행 VM
  Views/MainWindow.axaml     창 하나가 전부
  Styles/Controls.axaml      색·아이콘·컨트롤 스타일 (여기만 고치면 테마가 바뀝니다)
Tests/Flow.Tests/            소스를 직접 참조하는 콘솔 테스트
```

**기술 스택:** Avalonia UI 12.1.2 · .NET 10 · CommunityToolkit.Mvvm

`DayEngine`은 Avalonia에 전혀 의존하지 않는 순수 함수 모음이라, 시스템 시계를 건드리지 않고 며칠치 시나리오를 그대로 테스트할 수 있습니다.

## 알려진 제약

- Windows 전용입니다 (트레이·전역 단축키·자동 시작이 Win32 API를 씁니다). Avalonia 기반이라 macOS·Linux 이식은 가능하지만 그 세 기능은 다시 만들어야 합니다.
- 창 높이는 기본적으로 내용에 맞춰 자동으로 늘고 줄며, 직접 조절하면 그 크기를 기억합니다(폭 280~680px, 높이 최대 1100px).
- 알림·소리는 없습니다. 마감 시각은 표시만 됩니다.
- 다른 기기와 동기화하지 않습니다.
- 코드 서명이 없어 처음 실행할 때 SmartScreen 경고가 뜹니다. 자동 업데이트로 교체될 때는 사용자가 exe를 직접 실행하지 않으므로 마주칠 일이 적습니다.
